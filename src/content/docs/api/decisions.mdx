Give the model a piece of **state** (a message, ticket, call transcript, form record, or an image such as a receipt or screenshot) and **typed questions** about it. It answers every question in one pass, with a calibrated probability for every option.

| Model | Size | Input / 1M tokens |
| --- | --- | --- |
| [`purplemist-mini-2.0`](https://huggingface.co/olaverse/PurpleMIST-Mini-2.0) | 4.5B | <Price model="purplemist-mini-2.0" format="input" /> |

Decision models score every option rather than writing text, so there is no output charge.

## What PurpleMIST-Mini-2.0 can do

- **Answer many questions at once.** Up to 64 questions per call, of three types: pick one of several options (`choice`), say how likely a statement is true (`noul`), or place the state on a scale (`score`). They share one pass over the state, so extra questions cost almost nothing.
- **Read images.** Send receipts, invoices, screenshots or photos, alone or with text. A call can carry up to 16 images, which the model reads in order. With one image it is 0.984 accurate on held-out receipts and 0.907 on screenshots and real photos; accuracy is measured on single images.
- **Work in 19 languages.** English; Amharic, Hausa, Igbo, Nigerian Pidgin, Somali, Swahili, Yorùbá and isiZulu; and Arabic, Chinese, French, German, Hindi, Indonesian, Portuguese, Russian, Spanish and Turkish.
- **Ask in a different language from the input.** Write your questions once, in English say, and use them on messages in any of the 19 languages (0.937 accuracy on held-out cross-language questions).
- **Give probabilities you can act on.** Each question type is calibrated separately for text and images, so an answer given 0.9 is right close to 9 times in 10. Set thresholds on them: act automatically when the model is sure, and send the rest to a person.
- **Read long inputs whole.** Transcripts, logs and case files of up to 27,000 tokens are read in full, never cut short.
- **Accuracy.** 0.723 on LocalLLaMA/typed-decisions (English, zero-shot), 0.636 on African Typed Decisions across 8 languages, 46.5 on the Jev Decision Index text suite and 63.7 on its vision suite. That is the accuracy of the 7.9B PurpleMIST-Flash-1.0 on text, at about half the size.

### Good fits

- Routing and triaging support tickets, chats and emails: which team, how urgent, is it a complaint.
- Checking receipts and payment screenshots: does the total add up, is this a genuine bank or mobile-money confirmation.
- Moderation, fraud and KYC checks where you need a probability, not just a label.
- Replacing chains of prompted LLM calls that each answer one yes/no question.

### With an image

```python
import base64

with open("receipt.jpg", "rb") as f:
    receipt = "data:image/jpeg;base64," + base64.b64encode(f.read()).decode()

result = call("/v1/decide", {
    "state": {"note": "Customer says this is the receipt for their refund claim."},   # optional with images
    "images": [receipt],
    "questions": {
        "total_ok": {"type": "noul", "instructions": "The receipt total matches the sum of its line items."},
        "category": {"type": "choice", "instructions": "What kind of purchase is this?",
                     "criteria": {"food": "groceries or restaurant", "transport": "fuel, taxi or tickets",
                                  "other": "anything else"}},
    },
})
```

## Request

| Field | Type | Notes |
| --- | --- | --- |
| `model` | string | Optional. `purplemist-mini-2.0` (the default and only model). The `olaverse/PurpleMIST-Mini-2.0` form works too. |
| `state` | string, object or array | The thing being decided about. It must not be empty unless you send `images`. |
| `images` | array of strings | Optional. Up to 16 images as base64 or data URLs (`data:image/png;base64,...`), up to 16 MB each. Links are not fetched. |
| `assets` | object | Optional. Images in the System One format, referenced from the state, instructions or criteria. See [System One assets](#system-one-assets). |
| `questions` | object | 1 to 64 questions, keyed by your own IDs. |

`instructions` and criteria descriptions can be strings, JSON objects or arrays. `instructions` is optional for `choice` and `score`. Request bodies can be gzip or zstd compressed (`Content-Encoding`), up to 32 MB.

### Question types

| `type` | `criteria` | You get back |
| --- | --- | --- |
| `choice` | 1 to 255 option keys, each mapped to a description (or `null`) | `choice` (best key), `probabilities`, `confidence` |
| `noul` | Optional; `true` and/or `false` descriptions of when the statement holds | `noul`: the probability the statement is true |
| `score` | A list of 1 to 26 level descriptions, lowest first | `score` (expected level), `probabilities`, `legend`, `confidence` |

`box` questions are not supported; they return `400`.

### System One assets

Code written for System One works unchanged on `POST /v1/systemone`. Put a reference string where the image belongs, and the image under `assets`:

```json
{
  "state": {"photo": "a3f1c2e8-found", "note": "Customer says the parcel arrived damaged."},
  "assets": {"a3f1c2e8-found": {"type": "image", "format": "jpg", "data_base64": "/9j/4AAQ..."}},
  "questions": {"damaged": {"type": "noul", "instructions": "The parcel in the photo is damaged."}}
}
```

- `format` is `png`, `jpg` or `jpeg`; `data_base64` is plain base64, without a `data:` prefix.
- Use unique references such as UUIDs. Every asset must be referenced somewhere, or the request returns `400`.
- Images can also be sent as multipart: a `request` part holding the JSON, and one part per image, named by the asset's `part` field.
- The model reads images before the state, in the order they are first referenced; each reference becomes `[image 1]`, `[image 2]` and so on. Up to 16 images per request, counting `images` and `assets` together; each takes up to 1,024 of the 27,000 tokens.
- The `TypeSafe-Danger-Zone-Images` header is accepted and not needed.

## Response

Values are illustrative.

```json
{
  "model": "purplemist-mini-2.0",
  "answers": {
    "team":    {"type": "choice", "choice": "billing",
                "probabilities": {"billing": 0.98, "delivery": 0.02}, "confidence": 0.86},
    "refund":  {"type": "noul", "noul": 0.97},
    "urgency": {"type": "score", "score": 1.9,
                "probabilities": {"0": 0.05, "1": 0.25, "2": 0.45, "3": 0.25},
                "legend": {"0": "can wait", "1": "normal queue", "2": "today", "3": "immediately"},
                "confidence": 0.12}
  },
  "usage": {"input_tokens": 312, "output_tokens": 0, "decisions": 3}
}
```

## Reading the answers

- **Probabilities are calibrated,** so thresholds mean what they say. For example, act automatically above 0.9 and send the rest to a person.
- **`score` is the expected level.** 1.9 means "close to *today*". For the single most likely level, take the highest entry in `probabilities`.
- **`confidence` measures how peaked the distribution is** (0 = no idea, 1 = certain). It is not a second probability.
- **Ask several questions at once.** They share one pass over the state, so they cost no extra time.
- **Long inputs are never truncated.** A state of up to 27,000 tokens, images included, is read whole. Anything longer returns `413` with a "maximum context length" message, so split it into separate calls.
- **Images count as input tokens.** One token is a 32 × 32 pixel patch, and each image is scaled to at most 1,024 tokens (about one megapixel), so an image costs at most about <Price model="purplemist-mini-2.0" format="per-1000" tokens={1024} /> per 1,000 images.

## Batch

`POST /v1/decide/batch` takes up to **32 cases** per call. Give each case an `id` to match the results back:

```python
result = call("/v1/decide/batch", {
    "cases": [
        {"id": "t-1001", "state": "Refund me now!", "questions": {"refund": {"type": "noul", "instructions": "Asks for a refund."}}},
        {"id": "t-1002", "state": "Where is my parcel?", "questions": {"refund": {"type": "noul", "instructions": "Asks for a refund."}}},
    ],
})
for r in result["results"]:
    print(r["id"], r.get("answers") or r["error"])
```

Each case succeeds or fails on its own, so one bad case doesn't sink the batch. Failed cases come back as `{"id", "error", "status"}` (`400` invalid, `413` too long), and only answered questions are billed.
